# AWS 3-Tier Architecture: Database, Security & Bastion Host (Labs 6-8)

## 📌 Project Overview
This project is a series of hands-on labs implementing the Data Tier and Security for a 3-Tier Web Architecture on AWS using Terraform. The core objective is to provision a highly secure database, eliminate hardcoded credentials, and establish a secure tunnel for administration.

### 🏛️ Architectural Components:
1. **Lab 07 - AWS Secrets Manager:** Initializes a secure vault and automatically generates a random, high-entropy password for the database to prevent hardcoding credentials in the source code.
2. **Lab 06 - Amazon RDS (MySQL):** Deploys the core database deep within a Private Subnet. It dynamically retrieves the master password from Secrets Manager using the Terraform `data` source block.
3. **Lab 08 - Bastion Host (Jump Box):** A secure connection gateway provisioned in a Public Subnet, allowing Administrators to securely SSH into the internal network and interact with the Database and private EC2 instances.

---

## 🔒 Security Highlights
* **Zero Hardcoded Secrets:** Applies the Externalize Secrets approach. The DB password is auto-generated by AWS and stored securely in Secrets Manager.
* **Security Group Chaining:** The Amazon RDS firewall is configured statefully and strictly accepts inbound traffic on port `3306` only from the Web Server and Bastion Host Security Groups. No static IP addresses are whitelisted.
* **Network Isolation:** Amazon RDS has no Public IP (`publicly_accessible = false`) and is fully protected by the Private Subnet layer and isolated routing (Route Tables).
* **Git Protection:** Integrated `.gitignore` to completely block `.tfstate`, `.tfstate.backup`, and `.tfvars` files, preventing infrastructure state and sensitive data leakage to public repositories.
